# Облачная сборка GromVisuals (без Gradle на твоём ПК)

Workflow поддерживает оба варианта размещения файлов: Gradle-проект прямо в корне репозитория или внутри папки `GromVisuals/`. Это важно, если на GitHub загружали распакованную папку целиком.

## 1. Создай репозиторий GitHub
1. Открой https://github.com/new и войди в свой аккаунт.
2. Назови репозиторий `GromVisuals`.
3. Нажми **Create repository**.

## 2. Загрузи проект
1. Распакуй ZIP.
2. Открой репозиторий на GitHub.
3. Нажми **Add file → Upload files**.
4. Перетащи содержимое проекта. Убедись, что в репозитории есть `.github/workflows/build.yml` и Gradle-файлы `build.gradle`, `settings.gradle`, `gradle.properties`. Они могут лежать в корне или в `GromVisuals/`.
5. Нажми **Commit changes**.

## 3. Запусти облачную сборку
1. Открой вкладку **Actions**.
2. Выбери **Build GromVisuals**.
3. Нажми **Run workflow → Run workflow**, если сборка не запустилась после commit.

## 4. Скачай JAR
1. После успешного запуска открой его страницу.
2. Внизу найди **Artifacts**.
3. Скачай `GromVisuals-Minecraft-1.21.11`.
4. Распакуй ZIP-артефакт и найди `.jar`.
5. Помести JAR в `%AppData%\\.minecraft\\mods` вместе с Fabric Loader и подходящим Fabric API.

## Если сборка упала
Открой запуск в **Actions**, нажми на шаг **Build Fabric mod** и скопируй первые строки ошибки из лога. Сам факт, что артефакт не появился, означает, что сборка не дошла до успешного завершения.

## Важно
Gradle запускается на GitHub-hosted runner, а не на твоём ПК. JAR публикуется только после успешной сборки. Если исходный код или версии зависимостей несовместимы, потребуется отдельное исправление по логу.


### Совместимость версий
В workflow используется Gradle 9.2.0 и стабильный Fabric Loom 1.14.10. Это согласует версию Gradle Plugin API с требованием Loom 1.14; предупреждения об устаревшем Node.js не являются причиной предыдущего падения.
